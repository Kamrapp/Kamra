# Plan Template

## Title

Short descriptive name.

Use the sections that matter for the work. For very small documentation-only or low-risk cleanup plans, keep entries brief and mark irrelevant sections as `N/A` rather than filling the template mechanically.

## Objective

What this plan should accomplish.

## Context Read

Files, docs, commands, or prior plans reviewed.

## Research Gate

Needed or not needed. If needed, summarize sources checked, decision impact, and remaining uncertainty.

## User Requests

Explicit requests from the user. Keep these separate from derived objectives and side suggestions.

## Discovery Questions

Focused questions asked before plan finalization, preferably with 2-3 concrete options when a decision is ambiguous.

## User Decisions

Decisions made by the user during planning.

## Current Reality

What the repository currently does that matters for this plan.

## Intended Direction

How the change should move the project toward the desired architecture or workflow.

## Scope

Required current work. Prefer the smallest solution that satisfies it.

## Optional Work

Useful additions that are safe to omit unless the user approves them.

## Deferred Work

Foreseeable followups that should be recorded rather than implemented now.

## Non-Goals

Explicitly excluded or speculative work.

## Assumptions

Assumptions that should be checked during implementation.

## Open Questions

Questions that affect scope, architecture, or risk.

## Side Suggestions

Useful ideas that are not part of current scope unless approved.

## Steering Notes

How the plan changed during discussion, and which earlier assumptions were revised.

## Implementation Steps

For each step, use existing repository code and native/platform capabilities before proposing a dependency, abstraction, or extension layer. Note the justification when one is necessary.
