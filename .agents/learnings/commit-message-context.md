# Commit message context

Meaningful Kamra commits should preserve the reasoning that makes the change useful to a later
reviewer. Keep the subject concise, then add a short body covering:

- the problem or user need;
- the essential behavior or design change;
- the practical value or boundary it protects; and
- optionally, the focused validation that supports the change.

Avoid process narration such as “I’m committing this now”. Tiny mechanical or documentation-only
changes may use a subject-only commit when the subject already explains the change.
